# Blueprint graph-editor contracts

Use the index to retrieve only the contract section relevant to the task.

## Graph-node lifecycle contracts

`blueprint_graph_edit` performs exactly one `add_node`, `move_node`, or `remove_node` operation. Every shape carries a caller-generated operation ID, exact mutable published-family Blueprint path, current 40-character snapshot, and stable 32-character local graph GUID. `add_node` additionally carries one retained 32-character action ID and `{x,y}` position; move carries one stable node GUID and position; remove carries one stable node GUID. Coordinates are bounded integers within ±1,000,000.

For `add_node`, the action catalog must still retain an identity bound to the same bridge, target generated class, asset, K2 graph/schema, snapshot, normalized filters, and optional pin context. The catalog scans its rebuild signature from the live Blueprint action database within the normal 20,000-spawner/one-second ceiling and reapplies Unreal's live filter. Unknown, expired, evicted, mismatched, or newly filtered identities return `invalid_action` before a transaction. No cached UObject pointer is trusted.

Creation invokes the resolved spawner once. A newly created node and all of its pins must carry persistent Unreal GUIDs; the result lists those `created_identities`. A unique spawner may return an existing node, which is not repositioned and is reported as `created: false` and `returned_existing: true`. Null, out-of-graph, over-limit, unstable, or over-256-pin results are explicitly restored and reject.

Move/remove resolve only by stable node GUID inside the exact graph. Local event graphs, editable user-function graphs, and local macro graphs are supported. Inherited, interface, construction, delegate/signature, intermediate, transient, non-K2, and other read-only graphs reject. Intermediate nodes, required entry/result/tunnel nodes, and any node for which Unreal returns false from `CanUserDeleteNode()` reject as `protected_node`. Removal breaks only the target node's existing links. Pin defaults, wildcard-aware connections, and explicit conversions are specified separately in [Pin-default and direct-connection contracts](#pin-default-and-direct-connection-contracts).

At most 2,048 nodes may be present in a mutable graph. Every result includes the exact `blueprint_family`. Every accepted edit uses one Unreal transaction, applies structural/non-structural Blueprint marking according to the K2 node, and returns the asset, operation, graph, new snapshot, dirty state, one complete bounded changed-node record, created/existing flags, and created identities. Postconditions are verified by node identity/position/absence plus authoritative snapshot inspection. Unexpected failure is undone; no-change spawner failure cancels the transaction. Re-inspection is required after every graph edit, compile, Undo/Redo, reload, reconstruction, or bridge restart.

## Pin-default and direct-connection contracts

`set_pin_default` carries the common operation/asset/snapshot/graph fields plus one stable `node_id`, stable `pin_id`, and one tagged canonical `default`. The pin must be an unlinked, supported, editable input in the exact live local K2 graph. Execution, wildcard, linked, orphaned, trashed, hidden-default, read-only, ignored, unstable, and reconstructed identities reject before a transaction. `{kind:"engine_default"}` resets the pin to its autogenerated default. Explicit Boolean, numeric, text/name/string/enum, hard/soft object, class, and asset references use the shared K2 codec. Non-default arbitrary structs and live-schema-invalid reference/container forms remain unsupported. Canonical text is limited to 512 characters.

Graph-edit pin lookup and result encoding use the same canonical structural-pin set as inspection. In particular, UE 5.8's hidden, untyped, unlinked, default-free derived `ErrorTolerance` input on `K2Node_PromotableOperator` is neither returned nor targetable because its GUID is regenerated on first reload without changing graph semantics. Typed, visible, linked, or default-bearing tolerance pins remain included.

`connect_pins` and `disconnect_pins` carry stable `from_node_id`/`from_pin_id` and `to_node_id`/`to_pin_id` pairs. `from` must be an output, `to` an input, both must belong to the exact graph, each pin may contain at most 64 links, and the proposed direction must not form a node cycle. Connection preflight calls the live K2 schema. Direct make and break-others responses are accepted; break-others replaces only the links named by that response. Live wildcard specialization and numeric promotion are also accepted without conversion opt-in. Endpoint pin/node reconstruction is detected by object/type/identity read-back; every live identity on a reconstructed endpoint is returned in `reconstructed_identities` and its complete bounded node record appears in `changed.nodes`.

`connect_pins` alone accepts optional `automatic_conversion`. Omission or `false` returns `conversion_required` without mutation when the schema requires a conversion node. `true` permits only the live schema's conversion response, preflights capacity for the published maximum of one inserted node, and includes that insertion in the same transaction. The inserted node and all pins must have stable GUIDs, stay within the 256-pin/64-link bounds, and form a reciprocal directed path from the requested output to input through only that node. Its node and pin IDs appear in `created_identities`, and its node record appears in `changed.nodes`. Disallowed conversions return `incompatible_pins`; duplicate, missing, cyclic, over-limit, unstable, or stale requests reject before a transaction.

Every accepted pin edit uses one transaction, modifies only the owning Blueprint/graph/nodes/pins, schema-selected links, and any explicitly permitted conversion node, verifies exact default/link/path postconditions, bounded node count, reciprocal links, stable live identities, and a new authoritative snapshot, then returns the new snapshot and a concise operation-discriminated change. Connection records report `connected`, `direct`, `automatic_conversion`, `wildcard_specialized`, `conversion_node_count`, and `replaced_link_count`. Unexpected insertion or verification failure is undone. Re-inspect after every edit, compile, Undo/Redo, reload, reconstruction, or bridge restart; use returned reconstructed identities only to interpret the completed result, then use fresh inspection identities for the next request.
