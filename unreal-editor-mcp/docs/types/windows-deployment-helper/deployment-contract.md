# Windows deployment contract

The stable `scripts/deploy_plugin_windows.py` entrypoint re-exports focused owners under `scripts/windows_deployment/`. Core discovery, verification, transaction, configuration, and workflow modules have no Tkinter dependency. The view constructs widgets; the controller owns validation, confirmation, background work, and events. Deployment calls `scripts/packaging` as a library and never imports the packaging CLI entrypoint.

The selected directory must exist, contain at most 4,096 immediate entries, and contain exactly one immediate `.uproject` file. The descriptor is bounded to 1 MiB, must be a JSON object, and may contain only a string `EngineAssociation` of at most 128 characters for discovery purposes. The Engine input defaults to the trimmed `UE58` value. A valid configured value remains selected; otherwise registry discovery examines at most 256 Epic Launcher entries and 256 registered user builds. The Engine root must contain `Engine/Build/BatchFiles/RunUAT.bat`, and its `Engine/Build/Build.version` is bounded to 64 KiB and must report integer major/minor fields of 5.8 or newer. Direct packaging and graphical deployment use this same Engine validator.

The helper always packages the fixed base descriptor. Independent Boolean selections optionally add the fixed `UnrealMCPGAS`, `UnrealMCPCommonUI`, and `UnrealMCPEnhancedInput` descriptors in that order; each companion receives the base descriptor as its UAT dependency. The disposable `UnrealMCPTestCompanion` fixture is not deployable through the GUI. Each `BuildPlugin` call uses `-Rocket`, `-NoP4`, `-UTF8Output`, and `-TargetPlatforms=Win64`. It does not use `-Unversioned`, so the results are compatible with the selected Engine build rather than an arbitrary Unreal installation. All selected packages must build and pass package verification before installation begins.

Binary installation reads each restored installed descriptor's non-empty `Modules` array before staging. It accepts at most 64 unique case-insensitive module names, each a path-safe Unreal identifier of at most 128 characters. For every declared module, installation retains only `Source/<ModuleName>/<ModuleName>.Build.cs` from that module's source tree, because Unreal Build Tool still needs each module rule to consume a precompiled plugin. Each module rule is bounded to 64 KiB. The helper inserts `bUsePrecompiled = true` immediately before the one expected `PCHUsage` assignment and rejects a missing, changed, or ambiguous source rule instead of guessing. It removes C++ implementation and headers, every `.dSYM` bundle, and files ending in `.pdb`, `.ipdb`, `.iobj`, `.idb`, `.ilk`, `.obj`, `.pch`, `.map`, or `.debug`, case-insensitively. When the user enables PDB crash symbols, the filter retains only `.pdb` files directly under `Binaries/Win64` whose case-insensitive basenames match DLLs there; every deployed DLL must have a match. Packaged `Intermediate` precompiled manifests/import libraries remain. Each result must retain an installed descriptor, every declared precompiled module rule, and at least one direct Win64 DLL.

The exact install method is one of `project`, `engine_enabled`, or `engine_disabled`. Project destinations are `<Project>/Plugins/UnrealMCP` and, when independently selected, `<Project>/Plugins/UnrealMCPGAS`, `<Project>/Plugins/UnrealMCPCommonUI`, and `<Project>/Plugins/UnrealMCPEnhancedInput`. The `.uproject` `Plugins` array is bounded to 4,096 references; matching names are case-insensitive and must be unique, and the helper adds or sets `Enabled: true` for every selected plugin through an atomic same-directory replacement. Indirect/reparse-point project descriptors reject.

Engine destinations are `<Engine>/Engine/Plugins/Marketplace/<PluginName>`. `engine_enabled` writes `EnabledByDefault: true` into every installed descriptor; `engine_disabled` writes `EnabledByDefault: false`. Project descriptor state is unchanged for both Engine methods.

Any existing selected directory requires one explicit replacement authorization. The helper captures selected-destination existence and the exact project descriptor before the build, then rejects if either changes before commit. All packages are copied, configured, and verified in sibling staging directories before existing installations are renamed. The selected plugin set is committed as one transaction; failure restores every prior directory and prevents partial base/companion installation. On success, temporary staging and backup directories are removed.

An immutable `DeploymentRequest` supplies user choices. Planning resolves the fixed `PluginBuild` records, destinations, existing-state snapshot, optional project-descriptor update, and `EnabledByDefault` value into one immutable `DeploymentPlan`. Execution returns only the committed destinations in `DeploymentResult`.

One launch definition owns the stable `unreal-editor` server name, `command`, and ordered `args`. `command` is the absolute Python executable that launched the helper. `args` begins with the absolute checkout `server.py` path and exact selected `.uproject` path, which is the default readonly configuration. The independent writable choice appends `--writable`. The independent lifecycle choice appends `--editor-lifecycle` and the resolved selected Engine's existing regular `Engine/Binaries/Win64/UnrealEditor.exe`; a missing, relative, or differently named executable rejects. When both are selected, writable precedes lifecycle in deterministic argument order.

The GUI exposes exactly **Build log output** and **MCP settings preview** tabs. After successful installation, the preview renders the shared definition in one readonly, copyable text block as both a complete LM Studio `mcp.json` `mcpServers.unreal-editor` entry and a ChatGPT Codex `config.toml` `[mcp_servers.unreal-editor]` entry. Users merge only the applicable entry into the selected host file. The helper does not write host configuration or include the bridge token or generated project state.
