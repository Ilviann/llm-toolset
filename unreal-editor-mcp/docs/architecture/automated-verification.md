# Automated verification

## Python boundary

`tests/` uses `unittest` and injected bridge/platform collaborators. It covers immutable asset-family catalog validation and composition, duplicate/conflicting entries, unavailable native commands, MCP initialization/list/call, exact readonly/writable and lifecycle combinations, access rejection before bridge dispatch, exact schemas, result policy, stdout purity, discovery and token validation, stale/dead process rejection, loopback targeting, authentication headers, response bounds, timeout/cancellation, stable errors, platform branches, release consistency, fixed checkout-relative disposable-project resolution, host-specific headless editor selection, macOS-only `XCODE26_1_1` application-path derivation and developer-directory configuration, and the Windows binary deployment helper's project/Engine discovery, base/GAS/CommonUI/Enhanced Input packaging commands, project/Engine install modes, bounded multi-module source filtering and rule configuration, transactional replacement, enablement, and LM Studio/Codex settings previews. It does not require Unreal or a network.

## Native boundary

`AssetFamilies.ConformanceMatrix` uses one fixture runner for inspection-only,
creation-only, edit-only, combined, and missing-dependency descriptors, the
built-in Blueprint and neutral families, and a Game Data authoring fixture. It
covers deterministic adapter output, selectors, paging context, snapshots,
bounds, cleanup, stale rejection, transaction recovery, persistence, Undo/Redo,
and unrelated-state preservation without replacing family-specific semantic
tests.

`AssetFamilies.RegistrySelectionCapabilitiesAndFreeze` and `AssetFamilies.BoundedBuildersAndSyntheticAdapter` cover deterministic built-in family classification, independent adapter capabilities, unavailable dependencies, frozen ordering and fingerprints, and bounded semantic builders.

`Private/Tests/UnrealMCPAutomationTestSupport.h` owns shared fixture construction, argument builders, inspection helpers, snapshot tracking, save support, and cleanup conventions. `Readonly.PreservationAcrossReadonlyFlows` starts from a saved clean Blueprint and verifies unchanged package dirtiness and Undo history after success, rejection, bounded timeout, cancellation, retained rejected/committed lookup, and reconstructed post-restart services. `LevelInspect.ActorsComponentsPropertiesAndSafety` covers exact filters, descriptor/live fields, actor/component identities and reflected values, unsupported properties, pagination, stale snapshots, and unchanged editor state. `FunctionReplace.PreflightTransactionPreservation` covers scratch compilation, exact boundaries, one-transaction apply, Undo/Redo, stale rejection, live rollback, compilation, and saving. `NodeLayout.DeterministicChangedNodes` covers branches, joins, cycles, conversion keys, containing comments, fixed obstacles, repeated planning, and exact live replay. `WidgetTree.FamilyInspectionMutationAndPersistence` covers specialized creation, hierarchy/default inspection and edits, transactions, stale/reference rejection, compilation, saving, and read-back; `AssetInspect.UMGHierarchyLayoutBindingsAndExclusions` covers the model-facing effective hierarchy, presentation/layout, named slots, bindings, exclusions, paging, and preservation. `AssetDelete.PreflightPersistenceAndReferences` covers stale/reference rejection and verified persisted deletion; `AssetReferences.RegistryLiveMemoryAndCursors` covers registry/live evidence, exact snapshots, single-use and stale cursors, validation, missing-target rejection, and unchanged dirtiness. Phase 13 also covers canonical omission of UE 5.8's regenerated inert promotable-operator tolerance pin. `UnrealMCPApiProbe.cpp` keeps public Widget Blueprint/tree operation, structure-editor, Data Table, asset dependency, asset-editor, live-reference, non-force deletion, map loading, World Partition descriptor/reference, external-actor, package-state, and editor-delegate APIs in the normal compatibility build.

Normal/adaptive and forced-unity module builds are both required. Private implementation headers include their explicit Unreal dependencies, use named internal namespaces, and remain valid when Unreal Build Tool combines family translation units.

## Cross-process boundary

`scripts/asset_family_conformance.py` supplies common production-bridge identity,
determinism, snapshot, selector/page, retained-result, and restart read-back
checks. The Blueprint fixture preparation, Widget restart, Game Data lost-response
and restart, and test-companion scenarios opt into those checks through bounded
fixture records.

`widgets.py` owns focused Widget Blueprint creation, tree/default authoring, and exact restart read-back; keeping it separate avoids further growth of the already-large shared Blueprint scenario. Run `python scripts/run_headless_integration.py --widget-only` for the independent author/save/restart gate.

`scripts/run_headless_integration.py` is a thin executable and compatibility entry point. Scenario ownership lives under `scripts/headless_integration/`: `assets.py` verifies references and deletion; `blueprints.py` preserves the Blueprint scenario's public imports while `blueprint_fixture_preparation.py`, `blueprint_declarations.py`, `blueprint_graph_editing.py`, and `blueprint_restart_verification.py` own its four focused stages; `game_data_levels.py` owns typed game data and level switching; and `lifecycle.py` coordinates editor processes, Automation Tests, authentication, restart, shutdown, and scenario state handoff. The workflow resolves only the disposable `ue-test/ue58/UnrealMCPTest.uproject` descriptor from the application checkout, independent of the caller's working directory, and reads its Engine root from `UE58`; it accepts no project-path override. Before launch it writes a dedicated `Config/Tags/UnrealMCPTests.ini` containing only the deterministic project-defined Gameplay Tag fixtures used by native and production-socket tests; it never changes a committed or user project. It derives the headless editor from the detected host, selecting the macOS app binary, the Win64 command-line editor, or the Linux editor, requires `XCODE26_1_1` pointing to `Xcode.app` only on macOS, derives `Contents/Developer`, and uses Unreal's bounded memory DDC for isolated/offline runs. Each run removes its fixed-path generated fixtures before preparing them so retries do not depend on prior disposable project state. The workflow calls every released command family through the production Python client, reconciles deliberately lost mutations, and replaces a complete function, macro, custom-event handler, and native BeginPlay handler through the shared block-replacement engine. All four replacements use `layered_v1`; the native-event case preserves an exact conversion-to-PrintString external link. After compile/save and restart it verifies stable identities, layout/replacement fingerprints and owned sets, exact external/direct links, unrelated nodes, snapshots, catalogs, loopback binding, and clean heartbeat removal.

`readonly_mode.py` owns the production readonly acceptance scenarios. The complete workflow calls all nine readonly tools, follows representative single-page cursor continuations, exercises `level_open`, and compares the SHA-256/file-set snapshot of project-owned content before and after. The Windows `--readonly-lifecycle-only` path starts the exact ten-tool lifecycle-only server, rejects every writable tool before bridge dispatch, launches the real editor, restarts it with an exact bridge-instance change, shuts it down, and compares the project-content fingerprint. Generated and build directories, including bounded operational state under `Saved/UnrealMCP/`, are excluded. Windows passed both scenarios for the 0.28.0 release. The full readonly scenario passed again on macOS on 2026-08-15, but the separate lifecycle-only launch/readiness acceptance is still blocked by [`issue-4`](../issues/issue-4.md): the entrypoint rejects macOS and the direct helper's editor exits before bridge readiness. Linux execution is not required.

The cross-process workflow also authors every gameplay-framework family, typed Actor replication, a reliable server RPC, assigned default GameMode/GameInstance classes, one weapon-stat user-defined struct, and one typed balance table. It discovers serialized inbound references to that struct with bounded cursor continuation and repeats the evidence check after restart. It deletes a separate disposable unreferenced Data Table through a deliberately lost response, reconciles the retained result, and verifies absence before and after restart. It discovers and opens an exact mounted World through a deliberately lost response, reconciles and replays the operation, then exercises descriptor continuation, region filtering, exact actor/property inspection, and actor identity across restart while verifying the current-map snapshot remains stable. It then restores the native framework defaults with exact stale checks and verifies RPC/default/schema/row identities and values.

The Windows workflow passes the strict first-restart comparison for the Blueprint created through the production bridge. The resolved instability and exact changing field are recorded in [`issue-1`](../issues/issue-1.md).
