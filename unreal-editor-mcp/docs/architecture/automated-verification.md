## Python boundary

`tests/` uses `unittest` and injected bridge/platform collaborators. It covers MCP initialization/list/call, exact readonly/writable and lifecycle catalog combinations, access rejection before bridge dispatch, exact schemas, stdout purity, discovery and token validation, stale/dead process rejection, loopback targeting, authentication headers, response bounds, timeout/cancellation, stable errors, platform branches, release consistency, host-specific headless editor selection, macOS-only developer-directory configuration, and the Windows binary deployment helper's project/Engine discovery, base/GAS/CommonUI packaging commands, project/Engine install modes, filtering, transactional replacement, enablement, and LM Studio configuration. It does not require Unreal or a network.

## Cross-process boundary

`widgets.py` owns focused Widget Blueprint creation, tree/default authoring, and exact restart read-back; keeping it separate avoids further growth of the already-large shared Blueprint scenario. Run `python scripts/run_headless_integration.py --widget-only` for the independent author/save/restart gate.

`scripts/run_headless_integration.py` is a thin executable and compatibility entry point. Scenario ownership lives under `scripts/headless_integration/`: `assets.py` verifies references and deletion; `blueprints.py` preserves the Blueprint scenario's public imports while `blueprint_fixture_preparation.py`, `blueprint_declarations.py`, `blueprint_graph_editing.py`, and `blueprint_restart_verification.py` own its four focused stages; `game_data_levels.py` owns typed game data and level switching; and `lifecycle.py` coordinates editor processes, Automation Tests, authentication, restart, shutdown, and scenario state handoff. The workflow uses only the disposable `ue-test/ue58/` project and reads its Engine root from `UE58`. It derives the headless editor from the detected host, selecting the macOS app binary, the Win64 command-line editor, or the Linux editor, requires `UNREAL_MCP_DEVELOPER_DIR` only on macOS, and uses Unreal's bounded memory DDC for isolated/offline runs. Each run removes its fixed-path generated fixtures before preparing them so retries do not depend on prior disposable project state. The workflow calls every released command family through the production Python client, reconciles deliberately lost mutations, and replaces a complete function, macro, custom-event handler, and native BeginPlay handler through the shared block-replacement engine. All four replacements use `layered_v1`; the native-event case preserves an exact conversion-to-PrintString external link. After compile/save and restart it verifies stable identities, layout/replacement fingerprints and owned sets, exact external/direct links, unrelated nodes, snapshots, catalogs, loopback binding, and clean heartbeat removal.

`readonly_mode.py` owns the production readonly acceptance scenarios. The complete workflow calls all nine readonly tools, follows representative single-page cursor continuations, exercises `level_open`, and compares the SHA-256/file-set snapshot of project-owned content before and after. The Windows `--readonly-lifecycle-only` path starts the exact ten-tool lifecycle-only server, rejects every writable tool before bridge dispatch, launches the real editor, restarts it with an exact bridge-instance change, shuts it down, and compares the project-content fingerprint. Generated and build directories, including bounded operational state under `Saved/UnrealMCP/`, are excluded. Windows passed both scenarios for the 0.28.0 release; macOS execution remains preferred non-blocking follow-up evidence and Linux execution is not required.

The cross-process workflow also authors every gameplay-framework family, typed Actor replication, a reliable server RPC, assigned default GameMode/GameInstance classes, one weapon-stat user-defined struct, and one typed balance table. It discovers serialized inbound references to that struct with bounded cursor continuation and repeats the evidence check after restart. It deletes a separate disposable unreferenced Data Table through a deliberately lost response, reconciles the retained result, and verifies absence before and after restart. It discovers and opens an exact mounted World through a deliberately lost response, reconciles and replays the operation, then exercises descriptor continuation, region filtering, exact actor/property inspection, and actor identity across restart while verifying the current-map snapshot remains stable. It then restores the native framework defaults with exact stale checks and verifies RPC/default/schema/row identities and values.

The Windows workflow passes the strict first-restart comparison for the Blueprint created through the production bridge. The resolved instability and exact changing field are recorded in [`issue-1`](../issues/issue-1.md).
