# Windows deployment helper

`scripts/deploy_plugin_windows.py` owns the graphical source-checkout deployment workflow. Its tkinter UI selects one existing Unreal project folder and one Unreal Engine installation, runs the existing AutomationTool `BuildPlugin` contract for Win64, installs binary-only plugins into the project or selected Engine, and produces the exact LM Studio configuration for that project. The base plugin is always selected; one checkbox adds the `UnrealMCPGAS` companion and its base build dependency. `scripts/deploy_plugin_windows.cmd` is the Windows launcher.

The helper depends on `scripts/package_plugin.py` for trusted source-plugin identity, Engine structure validation, fixed AutomationTool arguments, protected output paths, and package verification. It reads only the selected folder's single immediate `.uproject` descriptor. The Engine input is initialized from trimmed `UE58` and preserves that value after project selection when validation succeeds. Without a valid configured value, discovery prefers the selected project's exact `EngineAssociation` in Epic Launcher/user-build registry records and the conventional Epic Games installation path. A user-selected Engine folder remains authoritative after its `Build.version` confirms Unreal Engine 5.8 or newer.

## Invariants

- Packaging is offline, targets only `Win64`, embeds the selected Engine version, and uses the fixed repository descriptors. GAS packaging passes the fixed base descriptor as its UAT dependency. After UAT completes, every source-owned base or companion descriptor field is restored before verification; only `Installed` and `EngineVersion` remain packaging-owned. Every selected package builds before installation begins.
- The deployment keeps each packaged descriptor, Win64 DLL, module rule, and precompiled build metadata, but omits C++ implementation/header source, object files, and debug-symbol bundles. External symbol/debug artifacts are omitted by default. The opt-in PDB checkbox retains only direct `Binaries/Win64` PDBs whose basenames match deployed DLLs. Every installed module rule explicitly sets `bUsePrecompiled = true`.
- Each installed descriptor must have `Installed: true`, a Win64 plugin DLL must exist, and no filtered debug artifact may remain. Symbol-enabled deployment additionally requires a matching PDB for every direct Win64 DLL.
- Project installation is confined to `<SelectedProject>/Plugins/<PluginName>` and atomically adds or enables exact `UnrealMCP` and selected `UnrealMCPGAS` references in the bounded immediate `.uproject` descriptor. Engine installation is confined to `<SelectedEngine>/Engine/Plugins/Marketplace/<PluginName>` and writes the chosen Boolean `EnabledByDefault` state into every installed descriptor. Reparse-point plugin paths, indirect project descriptors, and destinations outside the selected root reject.
- Any existing selected plugin is replaced only after explicit GUI confirmation. Copy and verification happen in sibling staging directories; temporary renames preserve all old selected plugins until every new directory is installed, verified, and project enablement succeeds.
- Build, verification, installation, or project-enable failure leaves existing selected plugins unchanged and never partially installs the companion pair. A selected destination or `.uproject` change observed while packages build rejects instead of overwriting newer state.
- The generated JSON invokes the current Python executable, the checkout's fixed `server.py`, and the selected absolute `.uproject` path. It is readonly by default. Independent GUI choices append `--writable` and/or `--editor-lifecycle` with the selected Engine's validated absolute `Engine/Binaries/Win64/UnrealEditor.exe`; it does not include the bridge token.
- AutomationTool output is streamed into the GUI without blocking tkinter's event loop. The window cannot close while deployment is active.

## Verification

`tests/test_deploy_plugin_windows.py` covers bounded project parsing and enablement, exact Engine-association candidate selection, 5.8+ validation, fixed base/GAS Win64 arguments, source-descriptor restoration, all three install methods, descriptor default state, default symbol filtering, opt-in matching-PDB retention and enforcement, guarded per-plugin precompiled-module rules, two-plugin replacement rollback, result verification, exact readonly/writable/lifecycle LM Studio JSON, and fail-closed lifecycle validation. `tests/test_package_plugin.py` continues to cover the shared packaging boundary, including rejection of stripped descriptor metadata. A native package build is required when source-plugin or packaging compatibility changes; the helper itself has no Unreal runtime behavior.
